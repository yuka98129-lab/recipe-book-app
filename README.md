# レシピ帳

見つけたレシピを材料・手順つきで保存し、カテゴリーだけでなく「時短」「ダイエット」「栄養重視」などの**用途タグ**でも探せる、レシピを覚えられない人のためのレシピ帳アプリです。

「今日は時間がない」「痩せたい」「栄養を摂りたい」といったその時々の目的に合わせて、保存したレシピをすぐに見つけられることを目指しています。

## 公開URL

https://recipe-book-app-nu.vercel.app

Vercel にデプロイしています。同期の設定をしていない間は、データはお使いのブラウザにだけ保存されます。ログインして同期を使うと、PC とスマホで同じレシピを見られます(下の「同期の設定」を参照)。

## 技術スタック

- [Next.js](https://nextjs.org/) 16(App Router)/ React 19 / TypeScript
- [Tailwind CSS](https://tailwindcss.com/) v4
- データ保存: ブラウザの **localStorage**(いつでも使える基本の保存先)。任意で [Supabase](https://supabase.com/) にもログインして同期できます(設定しなければ、サーバー・外部DBは使いません)
- テスト: [Vitest](https://vitest.dev/)

## 主な機能

- **レシピの登録・編集・削除**: 料理名、カテゴリー、用途タグ、材料・調味料(それぞれ名前と分量)、手順を保存できます。
- **材料グループ**: 「材料」「調味料」に加えて、「トッピング」のように名前を付けたグループをいくつでも追加できます(レシピの「カテゴリー」とは別の機能です)。「材料」は必須、「調味料」と追加グループは任意です。
- **入力のしやすさ**: 材料・調味料などの入力欄で、名前欄の Enter は同じ行の分量欄へ、分量欄の Enter は次の行の名前欄へカーソルを移します(次の行がなければ追加します)。日本語入力の変換確定の Enter では移動しません。空欄の行では行は増えません。
- **調理時間**: 1〜1440 分の整数で、任意で付けられます(全角の数字も使えます)。一覧とレシピ詳細に表示されます。
- **写真(1レシピに1枚)**: ログイン(同期)しているときだけ使えます。スマホではその場で撮影するか、写真から選べます。大きい写真は、長辺1280px・JPEGに自動で縮小してから、Supabase Storage(非公開)に保存します。一覧に小さく、詳細に大きく表示します。写真を使うには、`supabase/photos.sql` を1回実行します(`docs/同期の設定手順.md` の「写真を使うための追加手順」)。バックアップのファイルには写真の画像は含まれません(クラウド側にあります)。
- **用途タグ**: 「時短」「ダイエット」「栄養重視」「簡単」「節約」の候補から選ぶか、自由に入力できます。1つのレシピに付けられるのは最大3個です。
- **カテゴリー**: 主菜・副菜・汁物・主食・デザートから選べます。登録時に「新しいカテゴリーを追加」して増やすこともできます。
- **絞り込み**: カテゴリーと用途タグで絞り込めます。タグは複数選択でき、選んだタグをすべて含むレシピだけを表示します。
- **検索**: 料理名またはタグで検索できます(全角・半角の違いは区別しません)。
- **レシピ詳細**: 材料・調味料・追加したグループ・手順を、見出しごとに分けて表示します。
- **バックアップ**: 一覧画面の「バックアップ」から、全レシピを1つの JSON ファイルに書き出せます(エクスポート)。書き出したファイルを選ぶと復元できます(インポート)。読み込むときは、いまのレシピを残して加える「追加」(同じレシピは重複しません)と、すべて置き換える「上書き」(確認あり)を選べます。形式がおかしいファイルはエラーになり、データは変更されません。
- **同期(任意)**: Supabase にログインすると、レシピがクラウドにも保存され、PC・スマホなど複数の端末で同じレシピを使えます。ネットワークがつながっていないときの変更は端末に残り、つながったときに自動で送られます。いままで端末に保存していたレシピは、初めてログインしたときにクラウドへ送られます。
- **スマホ表示**: スマホの画面幅でも使えるようにレイアウトを調整しています。

絞り込みや検索の条件は URL に保持されるので、詳細画面から戻っても状態が保たれます。

## 起動方法

Node.js と npm が必要です(開発は Node.js 24 で確認しています)。

```bash
npm install
npm run dev
```

http://localhost:3000 をブラウザで開きます(ポートが使用中の場合は、起動時のログに表示される別のポートになります)。

その他のコマンド:

| コマンド | 内容 |
|---|---|
| `npm run build` / `npm start` | 本番ビルド / 本番サーバーの起動 |
| `npm run lint` | ESLint による静的解析 |
| `npm test` | Vitest による単体テスト(`npm run test:watch` でウォッチ) |

## データの保存について

**同期の設定をしていない場合**は、レシピはお使いのブラウザの localStorage にだけ保存され、外部には送信されません。そのため次の点にご注意ください。

- 別のブラウザや別の端末とは共有されません。
- ブラウザのサイトデータを削除すると、保存したレシピも消えます。定期的に「バックアップ」で書き出しておくと安心です。
- URL のオリジン(ホスト名・ポート)が異なると、別のデータとして扱われます(例: `localhost:3000` と `localhost:3001`)。

**同期にログインしている場合**は、上の保存に加えて、レシピの内容(料理名・材料・手順など)が Supabase のデータベースに保存されます。自分のレシピだけを読み書きできるように、行レベルセキュリティ(RLS)を設定します。ログアウトしても、その端末のレシピは消えません。

## 同期の設定

1. Supabase でプロジェクトを作り、[`supabase/schema.sql`](./supabase/schema.sql) を SQL Editor で実行します。
2. Authentication で自分のユーザー(メールアドレスとパスワード)を1人作り、新規登録を無効にします。
3. 次の環境変数を、Vercel(と、手元で動かすなら `.env.local`)に設定して、再デプロイします。

| 名前 | 値 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | プロジェクトの URL(`https://xxxx.supabase.co`) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 公開用のキー(anon key、または publishable key)。**secret / service_role キーは使わないこと** |

`NEXT_PUBLIC_` の値はビルド時にコードへ埋め込まれるため、変更したら**再デプロイ**が必要です。2つとも設定されていないときは、同期の欄が表示されず、これまで通りブラウザ内だけで動きます。詳しい手順は [`docs/同期の設定手順.md`](./docs/同期の設定手順.md) を参照してください。
